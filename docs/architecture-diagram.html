Bốn tầng — Frontend, API Gateway, Backend theo module, và tầng Dữ liệu — cùng 22 đường giao tiếp được đánh số. Mỗi số trên sơ đồ ứng với một dòng trong bảng bên dưới: ai gọi ai, bằng giao thức gì, truyền dữ liệu gì, đồng bộ hay bất đồng bộ.

Bảng mô tả luồng khớp theo số trên sơ đồ

№ Luồng Giao thức Dữ liệu truyền nhận Kiểu
1 Web App → API Gateway HTTPS / REST (JSON) Request kèm header Authorization: Bearer <access token>; body validate theo schema dùng chung trong packages/contracts. Đồng bộ
2 Admin Console → API Gateway HTTPS / REST (JSON) Giống (1) nhưng token bắt buộc có role=ADMIN; Gateway từ chối ngay ở biên, module quản trị không cần tự kiểm tra lại. Đồng bộ
3 API Gateway → Web App SSE · text/event-stream Sự kiện tiến độ job AI: { jobId, status, step, percent }. Trình duyệt không phải polling, giao diện cập nhật theo từng bước xử lý. Streaming
4 Gateway → Xác thực /api/auth/* Email + mật khẩu khi đăng ký/đăng nhập, refresh token khi gia hạn. Trả về access token ngắn hạn và hồ sơ người dùng. Đồng bộ
5 Gateway → Khóa học /api/courses/* Tạo, đổi tên, xóa và liệt kê khóa học. Mọi truy vấn đều lọc theo userId trong token để không lộ khóa học của người khác. Đồng bộ
6 Gateway → Tài liệu /api/documents/* Metadata file (tên, MIME type, dung lượng), yêu cầu cấp URL upload, và trạng thái xử lý: uploaded → extracting → ready | failed. Đồng bộ
7 Gateway → AI Orchestrator POST /api/ai/generate Yêu cầu sinh bài học { courseId, documentId, options }. Trả 202 Accepted kèm jobId ngay, không giữ kết nối chờ LLM. Đồng bộ
8 Gateway → Học tập /api/learning/* Nội dung bài học, câu trả lời người học gửi lên, kết quả chấm và tiến độ hoàn thành từng lesson. Đồng bộ
9 Gateway → Quản trị /api/admin/* Danh sách người dùng, thống kê lượng dùng AI theo gói, nhật ký hoạt động hệ thống. Đồng bộ
10 Gateway → Thanh toán /api/subscriptions/* Danh sách gói cước, yêu cầu tạo phiên thanh toán, trạng thái đăng ký và hạn mức còn lại của người dùng. Đồng bộ
11 Xác thực → Redis Redis protocol Lưu refresh token / phiên đăng nhập kèm TTL, bộ đếm rate-limit theo IP và theo user, danh sách token đã thu hồi. Đồng bộ
12 Tài liệu → Object Storage S3 API · presigned URL Backend chỉ cấp URL có hạn dùng; trình duyệt PUT file thẳng lên storage. File gốc không đi qua API, chỉ metadata được lưu xuống DB. Đồng bộ
13 AI Orchestrator → Thanh toán Gọi nội bộ (HTTP/gRPC) Kiểm tra hạn mức trước khi tạo job: { userId } → { plan, remainingCredits }. Hết hạn mức thì trả 402 và không có job nào được tạo. Đồng bộ
14 AI Orchestrator → Hàng đợi BullMQ · queue.add() Đẩy job lesson.generate với payload { jobId, documentId, storageKey, userId }. Đây là ranh giới giữa vòng request và xử lý nền. Bất đồng bộ
15 Hàng đợi → AI Worker BullMQ consumer Worker nhận job theo concurrency cấu hình sẵn, có retry kèm backoff; job thất bại quá số lần rơi vào dead-letter để xử lý tay. Bất đồng bộ
16 AI Worker → Object Storage S3 GET Tải file gốc theo storageKey để trích xuất văn bản và chia chunk trước khi gửi cho LLM. Đồng bộ
17 AI Worker → LLM Provider HTTPS API Gửi prompt kèm chunk văn bản, nhận JSON có cấu trúc (lesson, exercise, đáp án). Output luôn được validate bằng schema trước khi tin. Đồng bộ
18 AI Worker → PostgreSQL Prisma · transaction Ghi lesson và exercise đã validate trong một transaction duy nhất — job lỗi giữa chừng không để lại bài học dở dang. Đồng bộ
19 AI Worker → Hàng đợi Redis pub/sub · job progress Publish tiến độ từng bước (trích xuất, chunk, gọi LLM, validate). Orchestrator subscribe rồi đẩy tiếp ra SSE ở luồng (3). Sự kiện
20 Các module → PostgreSQL Prisma Client Toàn bộ truy vấn nghiệp vụ của 7 module. Mỗi module chỉ đụng nhóm bảng thuộc phạm vi của nó; muốn dữ liệu của module khác thì gọi qua API nội bộ như (13). Đồng bộ
21 Thanh toán → Payment Provider HTTPS API Tạo checkout session với giá lấy từ bảng gói cước phía server. Không bao giờ dùng giá hay trạng thái thanh toán do frontend gửi lên. Đồng bộ
22 Payment Provider → Gateway Webhook HTTPS POST /api/subscriptions/webhook: xác minh chữ ký, xử lý idempotent theo eventId, rồi mới kích hoạt gói và nạp lại hạn mức AI. Sự kiện

Gói chỉ được kích hoạt khi webhook có chữ ký hợp lệ quay về — không kích hoạt theo redirect của trình duyệt.

Ghi chú kiến trúc

Tầng 3 vẽ theo ranh giới module, không phải theo số process. Hiện tại 7 module chạy chung trong apps/api dưới dạng modular monolith, còn apps/worker đã là process riêng. Vì mỗi module chỉ nói chuyện với module khác qua API nội bộ (đường 13) chứ không đọc chéo bảng của nhau, việc tách từng module thành service riêng về sau chỉ là đổi transport, không phải viết lại nghiệp vụ.

Đường nét đứt là chỗ hệ thống không kiểm soát thời điểm. SSE (3), tiến độ job (19) và webhook (22) đều đến bất chợt, nên cả ba đều phải chịu được việc nhận trùng hoặc nhận muộn — webhook xử lý idempotent theo eventId, còn SSE luôn gửi kèm trạng thái đầy đủ thay vì chỉ gửi phần thay đổi.

Hai chỗ tuyệt đối không tin frontend: hạn mức AI (13) và giá gói cước (21). Cả hai đều được tính lại ở server trước khi tạo job hoặc tạo phiên thanh toán.
